# 대협 어드민 프론트 기반

기존 클릭 목업을 React + TypeScript + Vite 프로젝트로 옮긴 개발 기반이다. 현재 디자인은 임시 기본값이며, `/`(기업 목록·상세)는 샘플 저장소만 연결되어 있다 — 실제 조사·메일 발송·운영 DB는 이 화면에 연결하지 않았다. 로그인·가입·OTP·회원 관리는 이 앱 범위 밖이다 — `apps/portal-frontend`가 `admin.ghsnu.com` 루트에서 담당한다.

## 페이지

| 경로 | 내용 | 데이터 |
|---|---|---|
| `/` | 기업 목록·상세 클릭 목업 | 샘플 저장소(localStorage), 실 백엔드 미연결 |

## 실행

Node.js 24 LTS를 사용한다 (.nvmrc 제공). Windows ARM의 시스템 Node 25에서는 빌드 프로세스 비정상 종료가 재현되어 지원 기준에서 제외했다. Node 24.19.0에서 최종 빌드를 확인했다. 저장소 루트에서:

```sh
cd apps/dh-frontend
npm ci
npm run dev
```

http://127.0.0.1:5173/ 로 접속한다. 기존 `prototypes/admin/`의 8765 목업과 별개다. 포트가 사용 중이면 조용히 다른 포트로 바꾸지 않고 오류를 낸다.

```sh
npm run typecheck
npm test
npm run build
npm run preview
```

빌드 결과는 `dist/`에 만들어진다. 브라우저에서는 npm으로 설치된 라이브러리 번들을 사용한다. 원본 목업의 CDN에 의존하지 않는다.

## 수정 위치

| 바꾸려는 내용 | 파일·폴더 |
|---|---|
| 색·글자·간격·모서리 | `packages/ui-shell/src/tokens.ts` — Ant Design 테마와 CSS 변수의 공통 원본(다른 앱과 공유) |
| 목록·상세 배치 | `src/pages/`, `packages/ui-shell/src/app.css`(공통 리셋·유틸리티 클래스) |
| 반복 UI·업무 패턴 | `src/components/` |
| 화면용 데이터·행동 타입 | `src/models/outreach.ts` |
| 데이터 연결 계약 | `src/services/outreachRepository.ts` |
| 로딩·저장·실패·중복 클릭 처리 | `src/hooks/useWorkspace.ts` |
| 샘플 기업·지정 템플릿 슬롯 | `src/mocks/fixtures.ts` |
| 샘플 저장·상태 전환 | `src/mocks/mockRepository.ts` |
| 실제 어댑터로 교체할 위치 | `src/main.tsx`의 repository 주입 |

UI → repository 인터페이스 → 샘플 또는 실제 어댑터 순서다. 화면 컴포넌트는 localStorage나 샘플 데이터를 직접 읽지 않는다. 조회 응답은 화면용 Workspace이며 테이블 설계가 아니다. 지금은 작은 데이터셋 전체 조회를 사용한다. 실제 연결에서는 목록 페이지 처리와 상세 조회를 팀원과 합의해 확장해야 한다.

## 현재 가능한 시연

- 기업 목록·작업/경로 필터, 요약 패널, 상세의 이번 컨택/기업 자료/발송 이력.
- 신규/무응답/재접촉/재협업 검토, 관계자 선택, 배포 전 접촉자 제외.
- 초안 명시 저장, 승인, 수신자 변경 시 재검토, 시연 발송의 읽기 전용 스냅샷.
- PM 역할로 새 차수/추가 탐색 시연, 다음 차수 건너뛰기 복귀.
- 응답 결과·사유 입력, 논의 중 기업 리스트업 제외.
- 운영·개발 설정에서 정상/느린 요청/빈 목록/조회 실패/저장 실패/권한 없음 재현.

템플릿은 네 경로 모두 미연결이다. 신규 생성 버튼 비활성은 의도한 동작이다. 핀브릿지의 기존 샘플 초안으로 편집·승인·발송 흐름을 확인할 수 있다. AI 재생성·버전 복원 UI는 미구현이며 기존 원본 목업은 비교용으로 유지한다.

## 저장·실패·동시성 범위

개발 데이터 키는 `dhbot-frontend-v1`이다. 예전 목업 저장 키를 가져오거나 덮어쓰지 않는다. 저장 실패 시 서버 성공처럼 화면을 바꾸지 않고 입력을 유지한다. 한 화면에서 요청 중에는 추가 변경을 막는다. `version`이 맞지 않으면 충돌을 알리고, 최신 조회 전 현재 입력을 복사하도록 안내한다. 초안은 미저장 상태에서 내부 이동·창 닫기를 경고한다.

브라우저 저장소의 버전 검사는 개발 시연이며 여러 탭의 원자적 동시성이나 운영 권한을 보장하지 않는다. 실제 서버에서 권한·정책·트랜잭션·멱등성을 구현해야 한다. 샘플 adapter는 실제 연결 실패 시 대체 성공으로 사용하면 안 된다.

실제 어댑터의 최소 계약: load/getTemplates/execute/search/reset. reset은 개발 전용이며 운영 UI에서 제거한다. execute는 타입으로 제한된 업무 명령만 받으며 UI의 임의 DB patch를 받지 않는다. 실제 연결 시 operationId, 작업 ID, 페이지 처리, 인증된 실행자를 추가 합의해야 한다.

## 수동 확인

1. 핀브릿지 초안을 수정 → 미저장 표시 → 저장 → 검토 완료 → 발송 시연 → 이력 본문 확인.
2. 저장 실패 시나리오에서 초안 저장 → 오류 안내와 입력 보존 확인.
3. 모먼트핏 무응답 확인 → 같은 차수 추가 연락 불가 확인.
4. 새 차수 시작 → 같은 기업 응답 확인 → 다른 관계자 제안 확인.
5. 브릿지랩 승인 → 관계자 탐색 → 박서연 제외 확인.
6. 새 차수 시작 취소와 추가 탐색이 기존 차수를 바꾸지 않는지 확인.
7. 필터 빈 결과, 조회 실패 재시도, 권한 없음, 느린 요청 중 반복 클릭 확인.

수주 확정·Notion 동기화·담당자 안내 후 동일 차수 예외 정책은 미정이다. 디자인 시스템의 브랜드 방향도 다음 작업으로 남겨둔다.

공식 참고: [Vite 시작하기](https://vite.dev/guide/), [Ant Design 테마](https://ant.design/docs/react/customize-theme/).

## 이번 작업의 검증 기록

- TypeScript 검사 및 배포용 빌드 통과.
- 정책·저장 경계 테스트 10개 통과: 동일 차수 제한/다음 차수, 기존 접촉자 제외, 미연결 템플릿, 승인 버전과 스냅샷, 승인 해제, 실패 저장, 필수 사유, 건너뛰기 복귀, 동시 변경 충돌, 추가 탐색.
- 브라우저에서 목록/요약/상세, 초안 편집·저장·검토·시연 발송과 이력 노출, 재접촉 승인 저장 실패 시 입력 유지 확인.
- 전체 라우팅의 브라우저 회귀 검사는 아직 미완료. 목록의 이전/다음 기업 단축 이동, 버전 복원은 원본과 완전 동등하게 옮기지 않았다.
- Ant Design을 포함한 초기 JS 번들이 약 995 kB(압축 약 313 kB)로, 빌드에 크기 경고가 있다. 운영 배포 전 분할 로딩 검토 대상이다.
- 설치 중 registry metadata 불일치를 피하려고 nanoid를 확인된 3.3.11로 override했다. package-lock.json으로 버전을 고정하며 재설치는 npm ci를 사용한다.

API 협의는 [전체 API 연결 명세](../../docs/admin/api-contract.md)를 참고한다. 현재 샘플 repository와 운영 API 제안의 차이를 포함한다.
