# 대협봇 화면 (`src/dh`)

기존 클릭 목업을 React + TypeScript + Vite로 옮긴 대협봇 화면이다. 현재 디자인은 임시 기본값이며, `/dh`(기업 목록·상세)는 샘플 저장소만 연결되어 있다 — 실제 조사·메일 발송·운영 DB는 이 화면에 연결하지 않았다. 로그인·가입·OTP·회원 관리는 portal 화면(`src/portal`, `/login`)이 담당한다. 실행·환경 변수·배포는 [apps/frontend/README.md](../README.md), API는 [backend/docs/dh.md](../../backend/docs/dh.md).

## 페이지

| 경로 | 파일 | 내용 | 데이터 |
|---|---|---|---|
| `/dh` | `Workspace.tsx` | 기업 목록·상세 클릭 목업 | 샘플 저장소(localStorage), 실 백엔드 미연결 |
| `/dh/listup` | `listup/main.tsx` → `LiveRoot` | 조사 결과 → 컨택 작업 | 공유 Supabase 세션 + 백엔드 API. 세션이 없으면 `/login`으로 |
| `/dh/listup?preview=1` | `listup/main.tsx` → `Root` | 기존 화면 시연 | 별도 샘플 저장소(localStorage) |
| `/dh/listup?selectionPreview=1` | 같음 | 전체 선택 검토용 샘플(48개 기업) | 저장하지 않음 |

## 신규 탐색·컨택 화면

`/dh/listup`은 실제 로그인 세션으로 후보 목록·조사 결과·연락처·컨택 목록을 조회한다. 컨택 시작, 수신자 선택, 명시적 메시지 생성, 초안 저장·승인 버튼은 서버 API를 호출한다. 실제 메시지 생성은 백엔드 AI 키와 조사 근거가 필요하다. 발송 완료 저장 API는 아직 없어 비활성화했다. 새 탐색 버튼은 서버의 분기·소스를 조회해 탐색을 접수하고 상태·탐색별 결과를 표시한다. 실제 조사는 백엔드 AI 키와 작업 실행기 연결이 필요하다. 연락하지 않음 저장은 아직 연결하지 않았다.

로컬에서는 프론트 `http://localhost:5173/dh/listup`, 백엔드 `http://localhost:3000`이다. 로그인은 같은 앱의 `/login`에서 한다. 리스트업 화면의 전역 스타일은 `listup/styles.css`에서 `.lu-scope` 안으로 한정돼 있다(다른 화면에 새지 않게). Windows ARM에서 Prisma 5 엔진을 실행할 때는 Node 24 **x64**가 필요하다. DB 마이그레이션·시드는 이 연결 과정에서 실행하지 않는다.

이하 시연 기능 설명은 `?preview=1`에 해당한다. 시연 데이터는 `dhbot-listup-frontend-v1`에 저장되며 실제 API 오류 시 시연 데이터로 대체하지 않는다.

- 분기·담당자별 기업 목록과 탐색 배치를 조회한다. 상세 패널에는 조사 결과와 관계자를 표시한다.
- 적합 판정과 연락처가 있는 대상에서 컨택 시작 → 수신자·채널 선택 → 메시지 생성 → 초안 승인 → 복사 순으로 진행한다. `#message=<companyId>` 진입만으로 생성하지 않는다. 초안 수정·수신자 재검토는 승인을 해제한다.
- 이메일과 LinkedIn 모두 사람이 직접 전송한다. 현재 백엔드에는 발송 결과를 저장하는 쓰기 API가 없어 완료 저장 버튼은 연결 대기로 비활성화했다. 기존 발송 기록은 유지한다.
- 이번 탐색에서 연락하지 않음은 미처리·발송 완료와 구분하며 되돌릴 수 있다. 현재 로컬 미리보기 기능이며 저장 API는 별도 연결이 필요하다.
- 공통 메시지 템플릿은 내부 구성원의 대외협력팀장 직급, 기업·수신자 정보, 목표 분기별 일정을 사용한다. 관련 협업 사례와 아이디어는 현재 예시 생성이며 AI 워커는 연결되지 않았다.
- 계정 선택은 권한 시연용이다. 실제 인증이나 서버 권한 검사를 대신하지 않는다. 기존 저장 데이터와 이미 발송한 메시지는 유지한다.

## 실행

Node.js 24 LTS를 사용한다(`apps/frontend/.nvmrc`). Windows ARM의 시스템 Node 25에서는 빌드 프로세스 비정상 종료가 재현되어 지원 기준에서 제외했다. 실행·테스트·빌드는 [apps/frontend/README.md](../README.md) 참고(`npm run dev -w apps/frontend` → http://localhost:5173/dh). 기존 `prototypes/admin/`의 8765 목업과 별개다.

## 현재 가능한 시연

- 기업 목록·작업/경로 필터, 요약 패널, 상세의 이번 컨택/기업 자료/발송 이력.
- 신규/무응답/재접촉/재협업 검토, 관계자 선택, 배포 전 접촉자 제외.
- 초안 명시 저장, 승인, 수신자 변경 시 재검토, 시연 발송의 읽기 전용 스냅샷.
- PM 역할로 새 차수/추가 탐색 시연, 다음 차수 건너뛰기 복귀.
- 응답 결과·사유 입력, 논의 중 기업 리스트업 제외.
- 운영·개발 설정에서 정상/느린 요청/빈 목록/조회 실패/저장 실패/권한 없음 재현.

템플릿은 네 경로 모두 미연결이다. 신규 생성 버튼 비활성은 의도한 동작이다. 핀브릿지의 기존 샘플 초안으로 편집·승인·발송 흐름을 확인할 수 있다. AI 재생성·버전 복원 UI는 미구현이며 기존 원본 목업은 비교용으로 유지한다.

## 저장·실패·동시성 범위

개발 데이터 키는 `dhbot-frontend-v1`이다. 예전 목업 저장 키를 가져오거나 덮어쓰지 않는다. 저장 실패 시 서버 성공처럼 화면을 바꾸지 않고 입력을 유지한다. 한 화면에서 요청 중에는 추가 변경을 막는다. `version`이 맞지 않으면 충돌을 알리고, 최신 조회 전 현재 입력을 복사하도록 안내한다. 초안은 미저장 상태에서 내부 이동·창 닫기를 경고한다.

브라우저 저장소의 버전 검사는 개발 시연이며 여러 탭의 원자적 동시성이나 운영 권한을 보장하지 않는다. 실제 서버에서 권한·정책·트랜잭션·멱등성을 구현해야 한다. 샘플 adapter는 실제 연결 실패 시 대체 성공으로 사용하면 안 된다.

실제 어댑터의 최소 계약: load/getTemplates/execute/search/reset. reset은 개발 전용이며 운영 UI에서 제거한다. execute는 타입으로 제한된 업무 명령만 받으며 UI의 임의 DB patch를 받지 않는다. 실제 연결 시 operationId, 작업 ID, 페이지 처리, 인증된 실행자를 추가 합의해야 한다.

## 수동 확인

1. 핀브릿지 초안을 수정 → 미저장 표시 → 저장 → 검토 완료 → 발송 시연 → 이력 본문 확인.
2. 저장 실패 시나리오에서 초안 저장 → 오류 안내와 입력 보존 확인.
3. 모먼트핏 무응답 확인 → 같은 차수 추가 연락 불가 확인.
4. 새 차수 시작 → 같은 기업 응답 확인 → 다른 관계자 제안 확인.
5. 브릿지랩 승인 → 관계자 탐색 → 박서연 제외 확인.
6. 새 차수 시작 취소와 추가 탐색이 기존 차수를 바꾸지 않는지 확인.
7. 필터 빈 결과, 조회 실패 재시도, 권한 없음, 느린 요청 중 반복 클릭 확인.

수주 확정·Notion 동기화·담당자 안내 후 동일 차수 예외 정책은 미정이다. 디자인 시스템의 브랜드 방향도 다음 작업으로 남겨둔다.

공식 참고: [Vite 시작하기](https://vite.dev/guide/), [Ant Design 테마](https://ant.design/docs/react/customize-theme/).

## 이전 검증 기록 (단독 앱 시절)

- TypeScript 검사 및 배포용 빌드 통과.
- 정책·저장 경계 테스트 10개 통과: 동일 차수 제한/다음 차수, 기존 접촉자 제외, 미연결 템플릿, 승인 버전과 스냅샷, 승인 해제, 실패 저장, 필수 사유, 건너뛰기 복귀, 동시 변경 충돌, 추가 탐색.
- 브라우저에서 목록/요약/상세, 초안 편집·저장·검토·시연 발송과 이력 노출, 재접촉 승인 저장 실패 시 입력 유지 확인.
- 전체 라우팅의 브라우저 회귀 검사는 아직 미완료. 목록의 이전/다음 기업 단축 이동, 버전 복원은 원본과 완전 동등하게 옮기지 않았다.
- 지금은 단일 SPA에서 dh 화면을 처음 들어갈 때만 불러온다(lazy). Ant Design을 포함한 공통 번들은 여전히 크기 경고가 있다.
- 설치 중 registry metadata 불일치를 피하려고 nanoid를 확인된 3.3.11로 override했다(`apps/frontend/package.json`). 루트 package-lock.json으로 버전을 고정하며 재설치는 루트에서 npm ci를 사용한다.

API 협의는 [전체 API 연결 명세](../../docs/admin/api-contract.md)를 참고한다. 현재 샘플 repository와 운영 API 제안의 차이를 포함한다.
