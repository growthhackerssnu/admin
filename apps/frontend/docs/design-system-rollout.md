# 전체 GH 어드민 디자인 시스템 적용

## 기준

대협에서 선택한 B 팔레트, Open Sans/Noto Sans KR, MDC 글자 크기와 역할별 간격을 전체 어드민의 공통 기준으로 사용한다. 화면의 필드, 업무 흐름, 접근 권한은 기존 동작을 따른다. 기본 컴포넌트는 shadcn을 사용하고, 기존 Ant의 복잡한 표·폼은 같은 토큰을 받는 어댑터로 적용한다.

## 작업 순서

- [x] 1. 토큰·폰트·테마 통합: tokens.ts를 원본으로 CSS 생성, Ant 테마 연결, 전역 토큰 중복 제거.
- [x] 2. 공통 AppShell·AppSidebar: 권한별 메뉴, 파란 로고, 연한 사이드바, 축소/모바일 동작 통일.
- [x] 3. 공통 컴포넌트: 버튼·입력·필터·상태·팝업의 역할과 스타일 통일.
- [x] 4. 그핵드인·관리자: 목록·프로필·승인·회원 관리·키 관리에 공통 레이아웃과 타이포 적용.
- [x] 5. NUT: 회계 표·금액 입력·모달·오류 표현에 공통 토큰 적용.
- [ ] 6. 로그인·앱 선택·로딩 및 전체 검수: 같은 폰트/팔레트 적용, 앱 간 이동과 반응형 확인.

## 완료 기준

- 기능: 타입 검사, 기존 기능 테스트, 운영 빌드 통과. 권한별 메뉴와 접근 가드를 유지한다.
- 시각: 각 화면 및 팝업이 공통 토큰 사용. 사이드바 #E1E7F3, 선택 메뉴 #F8FAFE, 로고 #01397C.
- 레이아웃: 페이지 바깥 간격은 20px, 일반 페이지의 본문 최대 폭과 대협의 전체 높이 작업 공간을 구분한다.
- 이동: 직접 진입과 앱 간 이동 결과의 색·폰트·간격이 같다. 이중 사이드바나 전역 main 스타일 침투가 없다.
- 검수 상태는 통과/실패/미확인으로 기록한다. 실데이터 변경이 필요한 기능은 시각 확인과 구분한다.

### 구현 내역

1. `tokens.ts` → 생성 CSS 및 Ant 테마를 연결했다. 루트에서 한 번 설치하며 옛 `installTokens()`와 대협 네이비 덮어쓰기는 제거했다. 기존 변수명은 새 역할 토큰의 별칭으로 유지한다.
2. 그핵드인·관리자·NUT은 `AppShell`, 대협은 기존 패널 구조를 사용하며 `AppSidebar`를 공유한다. 권한별 메뉴는 기존 `reachableApps()`를 사용한다.
3. 기본 Button/Tag는 공통 shadcn Button/Badge 어댑터로 전환했다. Ant Table/Form/Select/InputNumber/Modal은 검증·편집 동작을 유지하고 같은 테마를 받는다.
4. 일반 페이지의 가로 여백 20px, 본문 최대 1400px, 그룹 간격 24px을 연결했다. NUT의 금액·표·기간 선택과 HR의 카드·프로필·필터 순서는 유지했다.
5. 로그인·앱 선택·로딩에도 밝은 표면과 공통 폰트를 연결했다. 로컬 검수 설정은 기존 Supabase 프로젝트와 공식 API 주소를 사용하며 `.env.local`은 커밋하지 않는다.

### 남은 사항

- [ ] 선택한 계정으로 HR 목록/프로필, 회원 관리, NUT 및 대협 간 이동을 읽기만 하며 검수한다.
- [ ] 8개 디자인 원칙과 체크리스트의 전체 화면 증거를 보충한다.
- [ ] 운영 배포 전 위 검수 결과를 확정한다.

Ant의 복잡한 컴포넌트를 전면 shadcn으로 다시 구현하는 작업은 이번 범위에 포함하지 않는다. 기존 HTML 시안의 스타일도 운영 React 적용 대상과 구분한다.

운영 빌드에는 기존 500kB 초과 번들 경고가 남아 있다(루트 JS 약 818kB, gzip 약 255kB). 빌드 실패는 아니며, 지연 로딩과 청크 분리는 별도 성능 작업으로 다룬다.
