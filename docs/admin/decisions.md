# 설계 의사결정 배경

## 리스트업에서 모든 판단을 끝내지 않는다

실제 담당자는 회사 검색 시 적합성, 이전 컨택 중복, 재발송 여부를 한꺼번에 판단했다. 이를 기업 식별·이력 확인 후 신규/무응답/거절·보류/재협업 경로로 분리했다. 경로마다 확인할 정보와 다음 행동이 다르기 때문이다.

## 기업 맥락을 유지한다

단계별로 기업을 다시 찾는 대신 기업 중심 목록에 작업 범위 필터를 둔다. 빠른 확인은 요약 패널, 실제 작업은 전체 상세로 나눈다. 기업 자료와 발송 이력은 상시 참고 탭이고 이번 컨택은 현재 작업을 이어가는 공간이다.

## 판단 근거와 행동 결과를 먼저 보여준다

신규 기업 검토에서는 '연락할까요?' 같은 질문보다 판단 요약과 조사 출처를 먼저 보여준다. 수신자 선택으로 넘어가면 기업 판단 내용을 반복하지 않고 직위·연락처 등 관계자를 고르는 정보에 집중한다. 메시지는 다시 열기 버튼을 누르지 않고 바로 편집한다. 상태와 중복되던 가로 단계 표시도 제거했다.

모든 승인에 설명을 받지 않는다. 다른 관계자 제안과 재협업 진행에는 사유가 필요 없지만, 재협업을 진행하지 않는 결정에는 이유를 남긴다. '보류/제외'는 행동 결과가 모호해서 내부 결정 이름을 '이번 차수 건너뛰기/영구 제외'로 구체화했다.

## 실제 운영 기준으로 차수를 정의한다

초기에는 분기라고 불렀지만 달력과 실제 수주 시작 시점이 일치하지 않는다. PM의 새 탐색 시작을 기점으로 차수를 명시하고 추가 탐색은 같은 차수에 넣는다. 같은 차수 내 중복 연락 방지도 날짜 간격 대신 차수 ID를 기준으로 설계한다.

## 자동화 범위는 사람의 결정을 돕는 데서 출발한다

응답 톤 자동 판별을 전제로 하지 않고 사람이 확인 결과를 기록한다. 경로별 지정 템플릿은 연결할 자리만 만들었다. 수주 확정과 학회 Notion의 일치성은 필요성이 확인됐지만 아직 결정하지 않았다. 기존 Slack 서비스의 기능과 웹 어드민의 확정 정책·제안은 구분한다.

## 화면을 검토했던 질문

1. 지금 어떤 결정을 해야 하는가?
2. 그 결정에 필요한 정보와 출처가 그 자리에서 보이는가?
3. 불필요한 클릭·입력·선택지가 있는가?
4. 행동 후 무엇이 달라지고 다음에는 무엇을 하는가?
5. 나중에 결과와 당시 메시지를 다시 찾을 수 있는가?

경로 하나씩 끝까지 따라가며 검토한다. 목업의 화면 검토 완료를 인증·저장·동시성 등 운영 검증 완료로 해석하지 않는다.
