# 프론트 상태·오류·검증 기준
상태 코드와 처리 방식은 백엔드와 맞출 제안이다. 화면 라벨은 한국어로 유지해도 저장 코드는 분리한다.

## 서로 섞지 않을 상태
| 구분 | 코드 예시 |
|---|---|
| 컨택 경로 | new / alternate_contact / recontact / repeat_collaboration |
| 작업 단계 | company_review / recipient_selection / draft_review / ready_to_send / response_check |
| 응답 결과 | unchecked / no_reply / discussing / rejected / deferred / referred / closed |
| 내부 결정 | active / skipped_for_cycle / excluded_permanently |
| 비동기 작업 | queued / running / succeeded / failed |
| 발송 | queued / sending / sent / failed / unknown |

거절은 이번 제안의 결과이지 영구 제외와 같은 뜻이 아니다. 외부 보류도 내부 건너뛰기와 같지 않다. 논의 중은 리스트업에 올리지 않지만 기록이 삭제되는 것은 아니다. 현재 목업은 여러 개념을 stage에 섞어두었으므로 그대로 가져가지 않는다.

## 확정 규칙과 적용
- 신규 검토에는 건너뛰기 없음. 영구 제외 가능.
- 다른 관계자 제안은 승인 사유 없이 진행.
- 과거 거절·보류 재접촉은 사유·조건과 승인 메모 확인.
- 재협업 진행은 사유 불필요, 건너뛰기·영구 제외 시 사유 필수.
- 무응답 기업은 같은 차수에 사람/채널을 바꿔도 추가 컨택 불가.
- 다음 차수에 실제 무응답 확인 후 다른 사람에게 제안.
- 배포 전 LinkedIn 전용 이력은 신규 경로, 기존 접촉자는 후보 제외.
- 거절/보류 사유 카테고리 필수, 기타 설명 필수.
- 템플릿 미연결이면 생성 불가. 기존 초안은 보존.

## 화면 상태
| 상황 | 화면 처리 |
|---|---|
| 첫 조회 | 로딩 표시, 빈 결과 문구는 아직 표시하지 않음 |
| 조회 완료·0건 | 필터 일치 기업 없음 / 아직 후보 없음 구분 |
| 조회 실패 | 오류와 재시도, 성공한 이전 데이터를 오류와 구분 |
| 변경 저장 중 | 해당 버튼 비활성, 진행 표시, 반복 요청 방지 |
| 저장 성공 | 서버 반환값으로 갱신, 관련 목록·상세·이력 갱신 |
| 저장 실패 | 입력값 보존, 오류 위치와 재시도 |
| 작업 접수 | 작업 ID 보존, queued/running 표시 |
| 장시간 작업 | 재방문 시 같은 작업 조회, 페이지 이탈로 새 요청을 만들지 않음 |
| 템플릿 없음 | 연결 필요, 신규 생성 비활성, 기존 초안은 열람 가능 |
| 권한 부족 | 읽기 허용 범위 유지, 불가 행동과 이유 표시 |
| 저장 충돌 | 내 편집 보존, 최신 데이터 확인·다시 적용 선택 |
| 발송 결과 불명 | 완료라고 표시하지 않고 sendId로 조회, 새 발송 요청 금지 |

## 오류 코드 제안
VALIDATION_ERROR(필드별 오류), UNAUTHENTICATED(로그인), FORBIDDEN(권한), NOT_FOUND(삭제/접근 불가), VERSION_CONFLICT(다른 사용자 수정), ACTIVE_CYCLE_CHANGED(차수 변경), CONTACT_EXCLUDED(수신자 재선택), SAME_CYCLE_BLOCKED(추가 발송 제한), TEMPLATE_NOT_CONNECTED(연결 필요), JOB_FAILED(재시도 가능 여부), SEND_STATUS_UNKNOWN(결과 재조회).

## 편집·확정
추천: 초안 편집은 로컬 입력을 유지하며 명시 저장 또는 합의된 지연 저장. 저장 완료를 DB 성공 전 표시하지 않는다. 승인에는 마지막 저장 revision을 사용한다. 주제·본문·제목·수신자 변경 시 재검토. 서버 정책과 반드시 일치시킨다.
수신자 변경으로 기존 본문이 바뀌지 않으면 인사말 확인을 안내한다. 이 동작은 현재 목업에 남은 QA 항목이다.
발송 스냅샷은 읽기 전용. 기존 발송 본문 수정과 현재 초안 수정은 별개다.

## 합의 후 검증할 시나리오
1. 새 차수 시작 취소는 차수 없음, 추가 탐색은 시작 시점 유지.
2. 같은 요청 재시도는 차수/탐색/발송 중복 생성 없음.
3. 두 사람이 동시에 새 차수 시작·기업 발송 시 충돌 처리.
4. 건너뛰기는 다음 차수 복귀, 영구 제외는 유지, 논의 중은 계속 리스트업 제외.
5. 다른 관계자·다른 채널로 동일 차수 제한 우회 불가.
6. 배포 전 접촉자는 신규 경로에서도 선택/발송 불가.
7. 기타 공백 설명 저장 불가, 리소스 부족은 선택 설명 없이 저장 가능.
8. 최신 응답 결과·시각·확인자와 이력이 새로고침 후에도 일치.
9. 미연결 템플릿 생성 불가, 연결 후 ID/버전 기록, 기존 초안 자동 덮어쓰기 없음.
10. 저장 충돌·네트워크 실패 시 사용자 입력 보존, 승인 후 수정 시 재검토.
11. 발송 실패/결과 불명/성공 구분. 성공한 발송 스냅샷 유지.
12. 비멤버·권한 없는 사용자의 접근을 서버가 차단. 프론트 숨김만으로 끝내지 않음.
