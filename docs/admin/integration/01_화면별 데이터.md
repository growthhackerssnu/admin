# 화면별 필요한 데이터
아래 영문 필드명과 객체 분리는 제안이다. DB 테이블 이름을 강제하지 않는다.

## 1. 공통 식별·상태
| 객체 | 프론트가 필요한 정보 |
|---|---|
| 사용자 | userId, displayName, 소속/멤버 여부, capabilities(가능 행동) |
| 수주 차수 | cycleId, name, startedAt, startedBy, endedAt, 현재 차수 여부 |
| 기업 | companyId, 이름·별칭, product, domain, website, 담당 내부 멤버, 영구 제외 여부 |
| 이번 컨택 건 | outreachId, companyId, cycleId, route, 작업 단계, 응답 상태, 내부 결정, version, updatedAt |
| 관계자 | contactId, companyId, name, role, department, LinkedIn URL, 연락처 배열 |
| 연락처 | endpointId, contactId 또는 기업 ID, channel, address, 유효성, 출처·확인 시점 |
| 조사 근거 | evidenceId, 요약, 원문 URL, 확인 시각, 샘플/실제 구분 |
| 초안 | draftId, outreachId, recipient/contact/endpoint ID, topic, subject, body, revision, 승인 버전, templateId/version |
| 발송 | sendId, outreachId, cycleId, 발송 상태, provider ID, 발송 당시 수신자·주소·제목·본문·템플릿 스냅샷 |
| 응답 | responseId, outreachId, 관련 sendId, result, category, explanation, revisitCondition, checkedAt, checkedBy |
| 작업 | jobId, type, status, error, 생성 결과 ID, updatedAt |

기업과 이번 컨택 건을 구분하면 같은 기업의 이전 차수 메시지를 덮어쓰지 않고 남길 수 있다. 같은 기업·차수의 복수 컨택 건 허용 여부는 합의 필요. 승인/응답/발송 시각과 실행자는 서버가 기록하고 화면에 전달한다.

## 2. 수집·새 차수 시작
읽기: 현재 차수, 사용 가능한 도메인·소스, 제외 조건, PM 시작 권한, 실행 중 탐색.
입력: 새 차수/현재 차수 구분, 새 차수 이름, 도메인·제품 형태·기업 규모·소스 등 지원 가능한 검색 조건.
반환: 확정된 차수, 탐색 jobId, 조건 스냅샷, 작업 상태.
확정 정책: PM이 시작. 새 차수 첫 새 기업 탐색 버튼을 누른 날짜가 시작점. 추가 탐색은 차수를 변경하지 않음.
합의 필요: 버튼 클릭 시각을 서버에 어떻게 남길지. 목업은 창을 연 시각을 기억하고 실행 시 확정함. 운영에서는 서버가 발행한 시작 의도 ID/시각을 활용하는 안을 제안. 취소·검증 실패는 활성 차수를 만들지 않음. 시작 후 탐색 API 실패는 차수 생성과 구분해 같은 작업을 재시도하는 안.

## 3. 기업 목록
요청: cycleId, 작업 범위, route, stage, ownerId, query, 정렬, 페이지/커서.
반환: items, total 또는 nextCursor, 탭별 개수(제공할 경우), currentCycle.
행: companyId/outreachId, 기업명·서비스·도메인, 경로, 현재 단계, 최근 발송 차수/시각, 담당자, 가능한 행동·불가 사유.
확정 정책: 기업 중심, 작업 단계와 경로 동시 필터. 논의 중 기업은 리스트업 제외.
합의 필요: 전체 탭이 전체 기업인지 현재 차수 작업 대상인지, 이전 차수 진행 건 노출, 검색 대상 필드, 정렬·페이지 방식. 목업 전체 목록을 그대로 최종 정의로 삼지 않음.

## 4. 요약 패널·기업 상세
패널: 기업 요약, 경로·다음 할 일, 최근 이력, 작업 불가 사유.
이번 컨택: 작업 상태에 따라 아래 정보 표시.
- 신규: 기업 판단 요약·출처.
- 무응답: 최근 발송, 마지막 응답 확인, 발송 차수, 기존 접촉자, 이번 차수 제한.
- 재접촉: 이전 거절/보류 결과, 사유 카테고리·설명, 원문 근거, 재논의 조건, 기존 담당자, 승인 메모.
- 재협업: 과거 협업 기록·노션 링크 자리. 진행 사유 불필요.
기업 자료: 상시 참고할 기업·조사·관계자 정보.
발송·컨택 이력: 날짜·행동·실행자·상세 링크, 원문 스냅샷. 문자열 배열 대신 구조화된 이벤트를 제안.

## 5. 수신자 선택
읽기: 후보별 이름·직위·부서, LinkedIn 활동과 조사 시점, 연락처, 추천 근거(기준 미정), 기존 담당자 여부, 선택 가능 여부·제외 사유.
저장: 이름 문자열이 아니라 contactId + endpointId.
확정 정책: 무응답 재컨택은 다른 사람. 동일인의 다른 이메일도 동일인. 배포 전 LinkedIn 기업은 신규 경로지만 기존 접촉자는 후보 제외. 기존 기록은 보존.
필요 이관 값: prelaunchOnly, 과거 접촉 contactId 또는 프로필 URL, companyId, 과거 기록. 동일인 ID 정리는 백엔드/이관 담당과 합의.
추가 정책 확인: 배포 전 기록 외에 현재 논의/배포 후 발송도 있는 기업의 우선순위. 무조건 신규로 덮어쓰지 않음.

## 6. 메시지 초안·확정
읽기: 수신자·주소, 주제·제목·본문, draft revision, 승인 버전, 적용 템플릿과 현재 연결 상태, 생성 작업 상태.
확정 정책: 경로별 지정 템플릿 연결만 준비. 미연결이면 안내. 기존 초안을 자동 덮어쓰지 않음. 최종 검토는 사람.
현재 배선 변수: companyName, product, recipientName, recipientRole, topic, senderName. 실제 지정 템플릿을 받은 뒤 필수/선택 변수 확정.
재생성 시 덮어쓰기·새 버전 선택, 과거 대화 맥락 반영, 버전 복원 범위는 별도 합의.

## 7. 응답·상태 관리
읽기: 최근 발송 내용·시각·차수, 최신 응답 확인 결과·메모·확인자·시각, 가능한 다음 행동.
입력: 답변 없음/논의 시작/거절/보류/담당자 안내/연락 종료, category, explanation, 보류 시 revisitCondition.
확정: 거절·보류 카테고리 필수(리소스 부족/무관심/문제 해결 수요 없음/기타). 기타 설명 필수. 무응답 확인 후 완료·다음 차수 재검토 표시.
미정: 논의 시작의 정확한 기준, 담당자 안내 예외, 연락 종료가 기업 영구 제외를 뜻하는지. 수주 확정 화면은 아직 없음.

## 8. 운영 설정
차수 시작 정보, 소스·카테고리 조회, 경로별 템플릿 연결 상태, 사용자 권한 범위.
템플릿 본문 편집 UI와 노션 연결 설정 UI는 현재 범위 밖. 실제 운영에서 샘플 초기화 버튼을 노출하지 않음.
