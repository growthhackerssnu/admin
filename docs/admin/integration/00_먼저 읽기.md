# 대협 어드민 프론트·백엔드 연동 정리
기준: 2026-09-22 피드백 반영 목업. 목적: 프론트와 DB 담당자가 병렬로 작업하기 위한 연결 규격 초안.

## 문서의 지위
- 확정 정책: 사용자와 합의한 업무 규칙. 01 문서에 표시.
- 연결 규격 제안: 필드명, 함수명, 상태 코드, 오류 코드, 충돌 처리 방식. 백엔드 구현과 조율 필요.
- 미정: 수주 결과 관리·노션 동기화·실제 발송 채널 등. 임의 확정하지 않음.
- 이 문서는 테이블 설계나 배포된 API 명세가 아니다. 기존 DB를 조회하거나 변경하지 않았다.

## 팀원에게 전달할 핵심
현재 app.js의 rows는 화면 시연용 통합 객체다. 기업 하나에 차수·초안·발송·응답이 섞여 있으므로 이를 그대로 DB 테이블로 옮기지 않는다. 프론트가 필요한 형태로 데이터를 조합해 주는 조회 결과와 행동 단위 저장 함수를 합의한다. API가 HTTP인지 SDK/RPC인지와 무관하게 같은 연결 규격을 사용할 수 있다.
실제 DB·인증은 담당 팀원이 구현한다. 프론트는 화면과 어댑터를 분리하고 샘플 어댑터로 먼저 개발한다. 실제 권한·연락 제한 검사는 서버가 최종 판단한다.

## 최소 연결 순서
로그인·멤버 권한 → 현재 차수·기업 목록 읽기 → 상세·이력 읽기 → 검토·수신자·응답 저장 → 초안 저장·승인 → 탐색/생성 작업 연결 → 실제 발송.
실제 조사·생성·발송 API 없이도 앞부분을 연결할 수 있다. 샘플 작업을 실제 발송 성공처럼 기록하지 않는다.
