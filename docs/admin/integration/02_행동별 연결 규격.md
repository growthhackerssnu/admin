# 행동별 연결 규격 초안
함수 이름은 프론트 어댑터 인터페이스 제안이며 실제 API 주소가 아니다. 모든 요청의 사용자 신원은 인증 세션에서 판정한다. 클라이언트가 보낸 owner/checker 이름을 실행자로 신뢰하지 않는다.

## 공통 응답 제안
성공: { data, requestId }. 실패: { error: { code, message, fieldErrors?, retryable }, requestId }.
조회 결과의 version/revision을 변경 요청의 expectedVersion/expectedRevision으로 보낸다. 충돌 시 최신 버전과 충돌 안내를 반환하고 임의 덮어쓰기는 하지 않는다.
중복 실행 위험이 있는 행동에는 operationId를 사용한다. 네트워크 오류 후 재시도는 같은 ID를 재사용한다.
시각: ISO 8601 UTC 전송, 한국 시간으로 표시. 값 없음은 null, 미확인 상태는 별도 값. 빈 문자열과 무응답을 혼동하지 않는다.

## 조회
| 함수 | 요청 | 결과 |
|---|---|---|
| getSessionContext | 없음 | 사용자, 소속, capabilities |
| getCycles | 페이지/상태 | 차수 목록, activeCycleId |
| getSearchOptions | 없음 | 도메인·소스·지원 조건 |
| listCompanies | cycleId, lane, route, stage, ownerId, query, pagination | 목록·전체 수/다음 커서 |
| getCompanyDetail | companyId, outreachId | 기업, 컨택 건, 근거, 상태별 데이터 |
| getHistory | companyId, cursor | 이벤트 목록·다음 커서 |
| getSentMessage | sendId | 읽기 전용 발송 스냅샷 |
| getContacts | companyId, outreachId | 선택 가능 후보·이전 담당자·제외 요약 |
| getTemplateBinding | route | 연결 상태, templateId/version, 필요한 변수 |
| getJob | jobId | queued/running/succeeded/failed, resultId/error |

## 변경·실행
| 함수 | 필수 요청·주요 입력 | 반환 및 화면 후속 행동 |
|---|---|---|
| startCycleAndSearch | operationId, 차수 이름, 검색 조건, expectedActiveCycleId, 시작 의도 정보 | cycle + job. 목록·차수 갱신, 탐색 상태 표시 |
| searchCompanies | operationId, cycleId, 검색 조건 | job. 기존 차수 유지 |
| approveCompany | outreachId, expectedVersion, 재접촉 승인 메모·확인 근거 | 갱신 컨택 건. 수신자 선택으로 |
| skipForCycle | outreachId, cycleId, expectedVersion, 사유 | 내부 결정·갱신 목록. 다음 차수 복귀 |
| excludeCompany | companyId, outreachId, expectedVersion, 사유 | 영구 제외·이력. 활성 목록에서 제거 |
| searchContacts | operationId, outreachId | job. 완료 후 후보 다시 조회 |
| selectRecipient | outreachId, contactId, endpointId, expectedVersion | 갱신 수신자·승인 상태. 서버가 제외 대상 재검증 |
| generateDraft | operationId, outreachId, recipient/contact/endpoint ID, topic?, expectedVersion | job 또는 draft. 템플릿 연결 여부 서버 확인 |
| saveDraft | draftId, expectedRevision, topic, subject, body | 저장된 revision·승인 무효화 결과 |
| approveDraft | draftId, expectedRevision | 승인된 revision, 시각·승인자 |
| requestSend | operationId, outreachId, draftId, approvedRevision, endpointId, cycleId | sendId + queued/pending 상태. 실제 발송 완료로 가정하지 않음 |
| saveResponse | operationId, outreachId, sendId?, expectedVersion, result, category?, explanation?, revisitCondition? | response + 갱신 컨택·가능 행동 |

기존 초안 이어보기는 generateDraft 호출이 아니다. 기존 draft를 조회한다. 새로 생성·재생성하는 작업은 사용자 명시 행동으로 실행한다.
수주 확정 저장·노션 동기화 함수는 정책 확정 후 추가한다. 현재 목록에 억지로 넣지 않는다.

## 요청·응답 예시: 보류 기록 (가상 ID)
```json
{
  "operationId": "op-response-001",
  "outreachId": "outreach-001",
  "sendId": "send-001",
  "expectedVersion": 4,
  "result": "deferred",
  "category": "resource_shortage",
  "explanation": "현재 담당 팀 리소스 부족",
  "revisitCondition": "차기 수주 차수에 일정 확인"
}
```
```json
{
  "data": {
    "response": {
      "id": "response-001",
      "result": "deferred",
      "category": "resource_shortage",
      "explanation": "현재 담당 팀 리소스 부족",
      "revisitCondition": "차기 수주 차수에 일정 확인",
      "checkedAt": "2026-09-22T03:00:00Z",
      "checkedBy": { "id": "member-001", "displayName": "담당자" }
    },
    "outreach": {
      "id": "outreach-001",
      "version": 5,
      "route": "recontact",
      "responseStatus": "deferred",
      "allowedActions": [],
      "blockedReasons": ["재논의 조건 확인 필요"]
    }
  },
  "requestId": "req-001"
}
```
예시의 allowedActions 빈 배열은 확정 정책이 아니라 대기 응답 예시다. 보류의 자동 복귀와 내부 건너뛰기는 별개로 합의해야 한다.

## 서버가 최종 검증할 것
- PM만 새 차수 시작 가능한지와 동시에 두 차수가 열리는 상황.
- 기업·이번 컨택·수신자·초안이 실제로 서로 연결되는지.
- 동일 차수 추가 연락 제한, 논의 중/영구 제외, 기존 접촉자 제외.
- 사유 필수 규칙과 승인 revision 일치.
- operationId 중복 요청, 상태 저장과 이력 기록의 원자적 처리.
- 외부 발송은 DB 트랜잭션과 동일하지 않음. 예약/접수 기록 후 전송 결과를 별도로 반영하고 결과 불명은 재조회.
