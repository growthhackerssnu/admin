# 정책과 미정 사항

## 확정한 업무 규칙

- 수주 차수는 달력상 분기가 아니다. PM이 수동 시작하며 첫 새 기업 탐색 버튼 클릭 날짜를 기점으로 삼는다. 같은 차수에서 추가 탐색할 수 있다.
- 목업은 탐색 창을 연 시각을 보관하고 실행 시 차수를 확정한다. 취소·입력 오류는 차수를 만들지 않는다. 운영에서 시각과 동시 시작을 처리하는 방법은 합의 대상이다.
- 무응답 기업은 동일 차수에 추가 연락하지 않는다. 다음 차수에 실제 무응답 여부를 확인하고 다른 사람에게 연락한다. 같은 사람의 다른 이메일·채널은 다른 관계자가 아니다.
- 논의 중 기업은 리스트업에서 제외한다. 정보 부족·이력 충돌은 별도 업무 경로로 만들지 않는다. 운영 데이터 오류 처리까지 없앤다는 뜻은 아니다.
- 내부 '이번 차수 건너뛰기'는 다음 차수 검토로 돌아온다. 영구 제외는 자동 복귀하지 않는다. 신규 검토에는 건너뛰기가 없다.
- 재협업 진행에는 사유를 요구하지 않는다. 진행하지 않는 결정에는 사유가 필요하다. 지난 협업 자료는 학회 Notion 링크 자리만 마련한다.
- 외부 거절·보류는 각각 기록한다. 사유는 리소스 부족/무관심/문제 해결 수요 없음/기타이며 기타는 설명 필수다. 사유만으로 영구 제외를 자동 결정하지 않는다.
- 배포 전 LinkedIn 전용 접촉 이력은 신규 경로로 취급하되 기존 접촉자는 후보 제외한다. 안정적인 관계자 ID·프로필 URL·이메일을 활용하고 이름만으로 동일인을 추정하지 않는다. 실제 이관은 미수행이다.
- 경로별 템플릿은 지정된 원본을 나중에 연결한다. 본문 편집용 관리 UI는 만들지 않는다. 미연결이면 신규 생성 불가, 기존 초안은 보존한다.
- 프로젝트 주제와 최종 메시지는 사람이 검토한다. 발송 당시 내용은 현재 초안과 별도의 읽기 전용 기록으로 남긴다.

## 목업의 템플릿 배선

`prototypes/admin/policy.js`의 신규 컨택/다른 관계자/재접촉/재협업 슬롯은 모두 null이다. 연결 객체는 `{id, version, subject, body}`이며 변수는 companyName, product, recipientName, recipientRole, topic, senderName이다. 적용 ID/버전은 생성 초안과 발송 스냅샷에 보존한다. 알 수 없는 변수는 생성 오류로 처리한다. 실제 원본 수령 후 필수·선택 변수를 다시 맞춘다. AI 재생성 API는 연결하지 않았다.

## 다음 구현 전에 합의할 사항

| 항목 | 남은 결정 |
|---|---|
| 수주·프로젝트 | 수주 확정 저장 위치, 프로젝트 생성 시점, Notion과 기준 데이터·동기화 방향 |
| 실제 발송 | 사람의 외부 발송 후 기록인지, 서비스 직접 발송인지, 지원 채널·성공 기준 |
| 관계자 평가 | 직위·LinkedIn 활동을 검색 조건으로 쓸지 조사 결과로 보여줄지 |
| 재접촉 초안 | 과거 대화·거절 맥락을 어떤 방식으로 반영할지 |
| 결과 기준 | 논의 시작의 정확한 조건, 담당자 안내 예외, 연락 종료와 영구 제외의 관계 |
| 데이터·권한 | 차수별 컨택 건 ID와 복수 건 허용, 전체 탭 범위, 멤버·PM 권한 |
| 차수 구현 | 시작 시각의 서버 기록, 동시 시작, 탐색 실패와 차수 생성의 분리 |

직원 50명 기준은 초기 아이디어이며 확정 제한으로 사용하지 않는다. 아직 미정인 내용을 이번 문서 PR에서 구현 정책으로 확정하지 않는다.
